# Decisions Log

Decisions made autonomously while the owner was away. Each can be revisited.

- **D-001 Stack**: TypeScript + Vite + three.js (WebGL2) + React for UI overlays. WebGL2 over WebGPU for laptop/browser compatibility.
- **D-002 Original IP**: All parts, art, names original. Agency name in-game: "Web Space Program". Crew are humans ("astronauts"), not a mascot species.
- **D-003 Scale**: Real data is the source; `s` scales lengths, GM by s² (preserves surface gravity), the atmosphere profile is compressed vertically by s^0.3 (standard → Earth atmosphere ≈ 70 km, like the genre classic), rotation periods by s^0.5. Default preset `standard` s=0.1. `real` preset uses exponent 1 for everything.
- **D-004 Rigid vessels**: Vessels are single rigid bodies (no wobbly joints). Structural failure via load thresholds. Removes KSP's "Kraken" class of bugs.
- **D-005 Gravity**: Patched conics for prediction and on-rails; physics mode uses dominant-body gravity, with optional n-body perturbations later.
- **D-006 Launch site**: Cape Canaveral-ish latitude (28.5°N) on Earth, east coast. Named "Coastal Launch Complex".
- **D-007 Autopilot building blocks** (`src/game/autopilot.ts`): planners (circularize, transfer to child/parent body, course correction) add maneuver nodes; controllers (ascent, node execution, powered landing) return a `ControlInput` per frame plus an optional `coastUntil` UT so any driver (tests now, an in-game autopilot later) can rails-warp idle phases. Node burns track remaining dv from measured proper acceleration and, for prograde/retrograde burns, stop on the planned orbital energy (finite-burn losses otherwise wreck near-escape burns like TLI). Landing = predictive suicide burn + slope-aware terminal descent (diverts to ground under ~8°). `tests/world-moon.test.ts` flies the stock Selene lander Earth → Moon landing → back into Earth's SOI with no balance changes.
- **D-008 Terrain relief**: relief scales by s^0.8 (standard: 0.16×) — slightly exaggerated vs radii for drama, but lunar slopes stay landable.
- **D-009 Tracking Station warp**: tracking uses the existing active-vessel warp clamps and encounter stops through `World.tick`; fleet focus is independent of the simulation's active vessel. With no active vessel, `advanceRailsTo` packs and propagates unattended vessels using existing rails event rules. Fleet conics refresh at 2 Hz while icon positions and floating-origin transforms update every frame.
- **D-010 Interplanetary targeting**: `src/game/interplanetary.ts` searches a scaled-ephemeris Lambert departure/flight-time grid, minimizes estimated ejection plus circular capture cost (capture optional), resolves the actual parking-orbit ejection plane and phase, and refines time/prograde/normal/radial against Earth → Sun → target patched conics. Prograde transfers with no complete extra revolutions only; exactly collinear Lambert endpoints are rejected as plane-ambiguous. Moon departure requires first reaching a planetary parking orbit. Ringrunner uses existing chemical engines and tanks, with no part balance changes; small late cruise trims are required because finite burns leave sub-m/s errors that matter over years. `porkchopGrid` exposes pure data for future UI work. The synchronous planner currently takes a few seconds; a worker is deferred.
- **D-011 Crew / EVA**: Crew are original human astronauts, generated from a persisted integer seed. Roster IDs live on command `PartState`s so staging and docking UID remaps preserve assignments. Catalog pod dry mass includes occupied seats (100 kg per suited astronaut); empty seats subtract that mass, preserving stock launch balance. EVA uses a runtime-only `eva-astronaut` part (95 kg dry + 5 kg monopropellant) and a dedicated DOM-free character step in the existing vessel/rails system. Hatch transfer preserves combined COM and linear momentum, with no separation impulse. Ground speed is 1.4 m/s walking / 3.5 m/s running, hop 2.5 m/s, slope limit 45°. Jetpack thrust is 35 N with 600 m/s exhaust velocity (~30.8 m/s total Δv). Boarding within 3 m of a free hatch and below 3 m/s relative speed services/refills the suit from abstract cabin supplies. Enter boards, leaving B available for aircraft brakes. Flags are body-fixed surface objects. Empty pods without a probe core accept no flight control or staging. Saves without crew data receive deterministic launch-style assignments on load.
- **D-012 Aircraft**: jets are `EngineModule`s with `airBreathing` (thrust = static thrust × Mach curve × (ρ/1.225)^k × intake-air fraction; fuel-only Isp, liquid fuel only). Intake air is produced every step and never stored (leftovers vented), so starvation at altitude/low speed is immediate; jets flame out below 15 % supply and relight automatically. Wheels are spring/damper suspensions with an impulse tyre model (lateral grip with sticky/sliding μ, rolling resistance, brakes inside a friction circle); steering fades with speed. Editor core now uses the catalogue surface-mount convention (srf node / −Z face); SPH crafts build horizontally (view-only rotation, craft +Y stays the nose) and launch on the runway (`World.launch(craft, 'runway')`, free on their wheels, no clamps).
- **D-013 Science / career**: `World.mode` defaults to `sandbox`; optional `SavedWorld.mode/progression` preserve version-1 saves. A vessel can store one observation of each subject at a time. Data lives on the instrument/pod/EVA part, follows splits/docking, and transfers into a pod on boarding. - **Art pass (2026-10-05, op/artpass):** Art direction, palette, material families and livery rules are in `docs/ART.md`.

  - **Decals:** Markings come from one procedurally drawn Canvas atlas through a single alpha-tested `decal` material.
